Pull vs Push — keep them distinct

Same GitHub connection; two jobs. V1 can ship either alone; they also stack with the editor review panel.

Pull (Git → Mermaid)Push (Mermaid → Git)
Job Bring a diagram that already lives in a repo into Mermaid AI so the user can open and edit it. Write Mermaid changes back to GitHub (commit / PR branch) after the user decides.
Typical entry Bot comment · Connect repo CTA · dashboard GitHub section · “open this .mmd”. After review Approve → Push to repo, or a later “save to Git” from a linked diagram.
Needs PR review UI? No for V1 open-only. Opening a file is enough — normal editor, no Discard/Approve bar. Optional. Full review panel when the change came from a PR diff; not required for a plain linked file save.
Prototype today Gate + seed into unified editor; dashboard Connected repos + Connect CTA. Review action bar stages: Approve → Pushing → Pushed to → merged pill.
V1 can be open-only (both ways). Ship a thin loop first: pull = open a GitHub .mmd in Mermaid; push = write that diagram back to the same path/branch — without the PR review panel (no diff counts, no Discard/Approve). The review panel is an additive layer on the same editor when the entry was a PR change, not a separate product.

How they live together in the editor

  • Always shared: unified canvas, AI sparkle, linked-repo metadata (owner / repo / file), dashboard GitHub section.
  • Open-only mode (V1 thin): diagram loads like any Mermaid file; pill may show repo/PR as a link badge only — no review actions.
  • Review mode (additive): same editor + top Discard/Approve (or Push stages) + green/red diff affordances + soft-dismiss via AI. Pull brought the before/after in; push sends the approved after back.
  • Vice versa: user can start in Mermaid (create/edit), connect GitHub, and push a new or updated diagram into the repo — still without requiring a PR-review session.

02

User flows

Thin V1 (open) vs full review+push. Same editor shell.

A · V1 open-only (no PR review panel)

  1. Pull open. From PR comment, Connect CTA, or Linked file → sign-in if needed → diagram opens in the unified editor as a normal linked file.
  2. Edit in Mermaid. Full AI / Build / Code — no Discard/Approve bar.
  3. Push back (optional). Save / write to the same Git path (vice versa: start in Mermaid → connect repo → push diagram up). Still no review chrome required.

B · PR review + push (what the mimic demos today)

  1. Open from PR. Bot comment → Open full review → login gate (repo / PR #356 / file) → Sign in (mimic) → unified editor in review mode.
  2. Review on canvas. Green added nodes; pill #356 +6 -0; Design/Code via pill; Discard / Approve top-center; AI sparkle bottom-center (soft-dismiss / restart).
  3. Approve & push. Push to repo → Pushing… → Pushed to (purple) → merged pill/tag on dashboard.
  4. Dashboard. Personal excludes linked diagrams; GitHub → Connected repos + branded Connect CTA.

04

Spec highlights

  • Pull ≠ Push. Pull opens Git content in Mermaid; push writes Mermaid content to Git. Review UI is optional on top.
  • V1 open-only is valid — both directions without Discard/Approve.
  • Actions top / AI bottom when review mode is on (Martin, Jul 23).
  • GitHub green → purple — open/review vs merged / pushed-to chip.
  • One diagram per review when using review mode — no version history in v1.
  • Dashboard GitHub nav — Connected repos + branded Connect tile.
