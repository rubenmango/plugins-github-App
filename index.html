00

Pull vs Push — keep them distinct

Same GitHub connection; two jobs. V1 can ship either alone; they also stack with the editor review panel.

↓ Pull · Git → Mermaid

Bring a diagram that already lives in a repo into Mermaid AI so the user can open and edit it.

V1: just open

Entry: bot comment · Connect CTA · dashboard GitHub · open .mmd

↑ Push · Mermaid → Git

Write Mermaid changes back to GitHub (commit / PR branch) after the user decides.

V1: save / write

Entry: Approve → Push to repo, or save a linked diagram — review UI optional

V1 can be open-only (both ways). Review panel is an additive layer on the same editor when the entry was a PR change — not a separate product. Vice versa: start in Mermaid → connect → push up, still without review chrome.

05

Spec highlights

  • Pull ≠ Push. Pull opens Git content in Mermaid; push writes Mermaid content to Git. Review UI is optional on top.
  • V1 open-only is valid — both directions without Discard/Approve.
  • Actions top / AI bottom when review mode is on (Martin, Jul 23).
  • GitHub green → purple — open/review vs merged / pushed-to chip.
  • One diagram per review when using review mode — no version history in v1.
  • Dashboard GitHub nav — Connected repos + branded Connect tile.
  • On-demand pull, never background push — 63k Generate-from-Code vs 15 pre-commit regenerate in 30d.
  • Multi-diagram is a refactor, not a rewrite — the review list already ships in VS Code (PLUG-73); PLUG-82 extracts the shared diff component and is still To Do. Import produces many diagrams at once, so the one-per-review limit bites immediately.
